# dogsbay-xml-dita-tutorial-docs

The reader's walkthrough of the step-by-step DITA tutorial: one page per stage
branch of [dogsbay-xml-dita-tutorial](https://github.com/dogsbay/dogsbay-xml-dita-tutorial),
from an empty project to a complete Audacity user guide, with the exact files
to write and the commands to run.

Intended to be served at **https://dogsbay.ai/dogsbay-xml-dita-tutorial-docs/**.

Built with [DogsBay](https://github.com/dogsbay/dogsbay).

## Layout

```
content/            source markdown (DogsBay MD)
content/nav.yml     the sidebar
dogsbay.config.yml  site config
plans/              the site plan (tracked)
astro/              GENERATED by `dogsbay site build`
```

`content.sources[].from` is pinned to `dogsbay-md`, as in dogsbay-migrate-docs.

## Working on it

```bash
dogsbay site build     # content/ -> astro/
dogsbay site dev       # live preview at http://localhost:4321/dogsbay-xml-dita-tutorial-docs/
dogsbay site check     # link and structure audit
```

Every DITA file on a stage page is pasted from its stage branch
(`git show tutorial/NN-slug:path`), never written by hand, and the gate output
is from a real run. When a stage branch changes, change its page.

Pages contain DITA markup and brace-delimited text. Keep it inside inline code
or code fences, or the build evaluates it as template syntax.

## Deploying

`astro/wrangler.jsonc` targets Cloudflare Workers Static Assets on
`dogsbay.ai/dogsbay-xml-dita-tutorial-docs` and
`dogsbay.ai/dogsbay-xml-dita-tutorial-docs/*`, following dogsbay-xml-docs. The
worker name, the repo name and the `name` in `wrangler.jsonc` are all
`dogsbay-xml-dita-tutorial-docs`; keep them identical. `npm run build` in
`astro/` runs `astro build`, the Pagefind index and the base-path mount step.
